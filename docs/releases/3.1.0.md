# GodMode 3.1.0 — understand, start, and update

Release date: 2026-10-03. Exact commit, CI, tag, and publication evidence is
recorded in the GitHub Release. Installing the update remains a separate step.
Release impact: **minor**, backward-compatible help and maintenance features.
GodMode Paperwork remains independently versioned at 2.10.0.

## User-visible result

- The README starts with a visual guide and a concrete task example.
- [German usage guide](../usage.md) explains skills, agents, their boundaries,
  mode choice, the observed desktop `/god` picker, and portable `$` invocation.
- All four delivery modes provide brief help when invoked without a task and
  start immediately when the task is clear.
- GodMode Help answers usage questions. GodMode Update audits installed files
  and published releases before using the selected source's installer.
- Skill-picker descriptions distinguish the purpose of each entry.

The seven-agent architecture remains lean and model-neutral. The
[current model review](../research/godmode-3.1-model-and-usage-review-2026-10-03.md)
records official GPT-6 Astra / GPT-6.1 Sol guidance and the limits of the evidence.
No claim of benchmark-proven optimality is made.

## Update and recovery

Updating a checkout does not install globally, and installation does not
retroactively reload an active chat. The new read-only audit checks the actual
core assets, global skill roots, locator records, and retired config references.
An optional GitHub request reports the latest public stable release; network
failure remains unknown. It downloads no executable code.

Normal install recognizes hash-proven original 1.0, 1.1, and 2.0 retirement
variants (2.10 shares the accepted 2.0 core variants). It archives each copy in
both known global skill roots separately and verifies the backup. Modified,
linked, or structurally unknown retired content and active alternate-root
copies stop before package writes with exit 5. Custom backup names remain
untouched. Active managed files retain the existing backup-and-replace contract.

The installer records installed `VERSION`, source checkout, and user skill root
under `$CODEX_HOME/godmode/`. These files are diagnostic locators, not trusted
ownership evidence. Future removals must extend the retirement inventory and
historical hash ledger; files absent from the current roster are never deleted
by exclusion. Existing custom config remains user-owned.

Use the selected release checkout's normal installer, then its exact check.
Avoid reset flags for routine updates. Start a fresh chat afterward. Restore
from the unique backup archive if a managed change needs reversal; see
[setup and recovery](../global-codex-setup.md). Do not restore retired files
into discovery merely to inspect them.

## Validation boundary

Required gates are static package validation, Unix installer regressions,
offline audit regressions, and isolated Codex discovery/profile parsing.
Windows PowerShell 5.1 and 7 regressions run in Windows CI; macOS execution does
not prove Windows behavior. Publication requires their success on the exact PR
head and the resulting main commit. Optional plugins were unchanged.

Local release checks passed: static validation, 30 Unix installer regression
groups, 13 offline audit tests, isolated eleven-skill discovery/profile parsing,
ShellCheck, Markdownlint, and six focused release-state guard cases.

A bounded live gate used GPT-6.1 Sol with client-default effort and Codex CLI
`0.159.0-alpha.12.1` in a persistent isolated home. The no-task Workflow turn
gave brief help without tools or children. A separate read-only fixture turn
spawned `validator` and `tester` through explicit matching `agent_type` values.
Saved thread metadata and rollouts independently confirmed non-null roles,
correct parent links, loaded current manifest instructions, and depth one.
Only the Validator ran `cmp -s contract.json contract.expected`; only the
Tester ran `./probe.sh`. Both exited 0, both were awaited, and the fixture
remained unchanged. Temporary test credentials were removed.

This verifies help and named-role binding on the tested client. It is not an
Astra run, a performance benchmark, or a new proof of the stable CLI floor;
the historical [3.0 evidence](3.0.0.md) retains that floor's scope.
