# GodMode Core 3.1.1 — Help for local rules and settings

Release date: 2026-10-04. Release impact: **patch** for Help troubleshooting;
display branding and product documentation have no runtime compatibility impact.
Exact commit, PR/main CI, tag and publication evidence is recorded in the GitHub
Release. GodMode Paperwork remains independently versioned at 2.10.0.

## User-visible result

GodMode Core Help explains usage and, for relevant diagnosis requests, compares
applicable global/project instructions and Codex settings read-only. Its
separately loaded procedure covers instruction overrides, configured fallback
files, profiles, session overrides, runtime visibility and current documentation.
Ordinary usage questions need no configuration scan.

Findings include source file/line references, the observed interaction,
expected effect and smallest optional remedy. Help distinguishes conflicts,
demonstrably shadowed or unavailable settings, confirmed legacy assumptions,
and optional simplifications. Deliberate model choices, stricter permissions,
extra repository gates and unrelated custom roles are legitimate preferences.
Unknown configuration layers or client identity stay unknown. A PATH-resolved
CLI version is not automatically the running desktop client's version.

The README now explains both Help uses, provides portable `$godmode-help`
examples, and separates rule diagnosis from Update's installation maintenance.
Help proposes changes; it does not edit settings, reset permissions, install,
or reconcile global files. Installation health is a separate Update diagnosis.

Current documentation, picker labels, the existing guide diagram and marketplace
display use GodMode Core for Codex. The product-family guide distinguishes the
self-installed Community packages from the separate proprietary Pro application.
Technical skill names, paths, repository URLs, marketplace IDs, licensing,
existing Pro commitments, seven optional roles and eleven skills are preserved.
Historical 3.0 and 3.1.0 release documents remain historical.

## Update and activation

Select the immutable `v3.1.1` tag, run the normal platform installer and its exact
check, then start a fresh Codex chat. No reset flag is needed for this patch.
Updating Git alone does not refresh the global installation or loaded context.
See [setup and recovery](../global-codex-setup.md) and the
[German usage guide](../usage.md#eigene-regeln-und-einstellungen-prüfen).

## Validation boundary

Release gates are static validation, focused Unix installer and audit suites,
isolated discovery/profile parsing, Markdownlint, and exact PR/main CI including
Windows PowerShell 5.1 and 7. The marketplace display change requires the plugin
validator; Paperwork itself and its version are unchanged.

Help's scoped behavior evidence was gathered on 2026-10-03 with GPT-6.1 Sol,
client-default effort and Codex CLI 0.159.0-alpha.12.1 in isolated synthetic
homes. One case identified missing required roles, selected instruction
overrides, inactive `AGENT.md`, and an explicit model override. Another preserved
intentional extra gates, model choice, read-only permissions and a user-owned
`researcher` role without false error findings. The client/PATH distinction was
corrected and retested. Saved graphs contained parent sessions only; command
evidence showed reads and version probes, no production checks or source edits.

The initial broad input snapshots also captured Git-index and client-cache
metadata; the focused comparison instead verified the actual reviewed project
files, global settings, managed skills/roles and custom-role content unchanged.
Temporary credentials were removed. Release preparation verifies that the final
tested Help files match the current package. This is bounded behavior evidence,
not an Astra test, a performance benchmark or a general installation-health proof.
